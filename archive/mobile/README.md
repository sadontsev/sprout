# Sprout — the iOS app

The Expo (SDK 56) / React Native app. Start with the [root README](../README.md) for the
whole-system picture; this covers only the app workspace.

## Commands

```bash
npm install            # postinstall applies patches/ via patch-package
npx tsc --noEmit       # type-check — must be clean before any build
npm test               # jest (jest-expo preset), pure-logic tests only
npx jest path/to.test.ts        # one file
```

## Building for a device

There is no `expo run:ios` and no EAS here — builds go through `xcodebuild` locally.
The exact, gotcha-annotated recipe (prebuild, signing, devicectl install, crash triage)
lives in the root [`CLAUDE.md`](../CLAUDE.md) — substitute your own team ID, bundle id
(`app.json` → `ios.bundleIdentifier` + `ios.appleTeamId`) and device UDID.

Key constraint: **`ios/` and `android/` are gitignored** and regenerated by
`npx expo prebuild --clean`. Never hand-edit them — durable native changes go through
config plugins in `plugins/`, `patches/` (patch-package), or `app.json`.

## Layout

| path | what |
|---|---|
| `src/api/` | typed Bambuddy client (all network goes through it) + response types |
| `src/realtime/` | WebSocket status hook, camera stream hook |
| `src/dashboard/present.ts` | pure status → view-model (the single source of print-state truth) |
| `src/ams/` | AMS drying view-model |
| `src/library/` | gcode layer-viewer parser/renderer, printer-file helpers |
| `src/app/` | expo-router routes (`index.tsx` = shell, `settings.tsx` = onboarding) |
| `src/components/` | screens, overlays, animation kit |
| `src/liveactivity/` | Live Activity widget (expo-widgets, `'widget'` directive) |
| `src/notifications/` | push-permission + device-token registration |
| `plugins/` | config plugins (unit-tested transforms) applied on prebuild |

## Onboarding

First launch asks for the **backend URL + API key**; both are stored in the iOS Keychain
(this-device-only). The push-service URL is derived from the backend host
(`bambuddy.` → `lapush.`) or set explicitly in the stored config.
